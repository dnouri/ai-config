# LLM Cliché Check

Use Simon Willison's live [LLM cliché highlighter](https://tools.simonwillison.net/llm-cliche-highlighter) as the source of truth. The bundled helper handles the browser interaction and returns only the counts and flagged passages:

```bash
node {baseDir}/check.js path/to/draft.md
```

It also accepts standard input:

```bash
node {baseDir}/check.js < path/to/draft.md
```

For prose currently held only in the conversation, write the exact candidate to a temporary UTF-8 file, scan it, and remove that file afterwards. Do not rebuild substantial prose with `echo` or shell quoting; those can alter the text being checked.

## Workflow

1. **Choose the exact deliverable.** Scan the text the user will publish, including its headings and list punctuation. Exclude your own commentary around it. When there are several short variants, put them in one temporary file and check them together; one browser run is faster and catches patterns across the complete package.
2. **Run the helper once.** It loads the current website with every available pattern enabled. Read `summary` first, then each entry in `flags`.
3. **Treat flags as editorial evidence, not verdicts.** The highlighter detects rhetorical patterns; it does not prove that text was generated by AI. Quoted material, deliberate repetition, and domain language may be worth keeping.
4. **Revise surgically when the user asked for revision.** Change the flagged sentence, preserving facts, voice, formatting, links, and length constraints. Do not flatten an otherwise natural draft or rewrite clean passages merely to reach zero.
5. **Rescan the entire final deliverable.** A revision can introduce another pattern. Repeat until the tool reports zero or the remaining hits are deliberate and explained.
6. **Report the measured result.** Give the three final counts. If hits remain, identify their pattern names and why they were retained.

If the user asked only to check or audit text, do not silently rewrite it. Return the flags with concise alternatives instead.

## Reading the report

The helper emits JSON shaped like this:

```json
{
  "patternsChecked": 38,
  "summary": {
    "matches": 1,
    "flaggedSentences": 1,
    "chainItems": 3
  },
  "flags": [
    {
      "sentence": "No fluff, no filler, no jargon.",
      "matches": [
        {
          "text": "No fluff, no filler, no jargon",
          "pattern": "“No X, no Y” chains",
          "note": "3 “no” items"
        }
      ]
    }
  ]
}
```

`matches` counts pattern hits; one sentence can contain more than one. `flaggedSentences` counts distinct highlighted passages. `chainItems` is the total number of items found in chain-style patterns.

For a clean result, say:

> Simon Willison's highlighter reports 0 matches, 0 flagged sentences, and 0 chain items.

Do not turn that into claims such as “AI-free,” “human-written,” or “free of clichés.” It means only that the current live patterns did not match.

## Reliability and privacy

The helper uses a unique, non-persistent browser session, waits for the website's self-tests, verifies that all patterns are enabled, blocks further network requests before inserting the prose, and cleans up its temporary files and browser session. It deliberately does not copy Simon's pattern list into this skill, so changes to the live tool take effect without maintaining a second implementation.

The page is still third-party code. Do not scan secrets or sensitive unpublished material without the user's informed approval.

If the website, browser, or network is unavailable, report that the check could not be completed. Do not substitute a remembered list of clichés while claiming it came from Simon's tool.
